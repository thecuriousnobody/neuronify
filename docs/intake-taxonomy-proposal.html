Smart Intake · Data-Model Proposal

A discrete 311 taxonomy for citizen intake

Replacing free-text categories with a real, 311-sourced taxonomy so a report routes straight to the owning department — and defining the category-specific fields the conversation collects. This is the research step; no code yet.

The two findings that shape everything

1 · Real 311 is two-level and department-owned. Peoria (Peoria Cares / uReport) uses category → issue type. Evanston (Catalis / QScend, read verbatim 2026-07-17) exposes 17 top-level options that are the owning departments, each expanding into request types. So the native shape everywhere is category → owning department → fields — exactly what we should model.

2 · Neither city collects category-specific fields. Both are flat forms — location + description + photo + contact, identical for every type. That makes our per-category required fields + conversational refinement a real differentiator, not catch-up.

Design consequence: the LLM's job shrinks to picking one discrete category. Category → department is a per-city lookup table (data). Category → fields is a form definition (data). The model proposes one enum value; everything downstream is deterministic and auditable.

Divergences to confirm — this is why the map is per-city data, not intuition

  • Rodents / pests: Peoria → Code Enforcement; Evanston → Health & Human Services.

3 · Category field schemas

The differentiator

Every category shares a base schema — location (required, asked early: Evanston gates the category behind location), description (required), and photo (required only for the photo-critical cluster). Then each adds its own attributes, with plain-language guidance in prompt. photo required marks the photo-critical cluster.

⚠ Dependency

Photo upload is currently stubbed (/api/v2/submit defers attachments). Real image upload + storage must ship first before any category can hard-require a photo. This is the #1 enabling task.

4 · How routing changes

More defensible than today

Today — classify()

  1. LLM emits free-text category (decorative).
  2. LLM also picks the department (allow-list clamped).
  3. The model owns the routing decision.

Proposed

  1. LLM discerns category_key from the discrete core (clamped + fail-safe to other_inquiry).
  2. Code looks up department = MAP[city][category] — deterministic, per-city.
  3. Code loads that category's form → runs existing runIntakeTurn.
  4. Category fields can sharpen severity (hazard=true → high; on_wires=true → safety-critical).

Routing becomes a lookup keyed on a validated enum, not a free model choice — easier to trust, audit, and reassign.

5 · Known model gaps to decide

  • No multivaluelist FieldType. Two categories want "choose several" (illegal_dumping.material, property_maintenance.issue). Either add a multichoice type, or keep single-select ("pick the main one"). Recommend single-select for v1 — no engine change.
  • Category disambiguation. When a report is ambiguous ("junk and tall grass in the vacant lot"), does the agent ask, or pick highest-confidence and let staff reassign (already built)? Recommend pick + reassign, clarify only on low confidence.
  • Anonymous + required photo tension. The photo-critical categories are exactly what anonymous users report. Until upload ships, soft-require (strongly ask, allow skip) rather than block.

6 · Sequencing

When we do build
  • 1 · Photo upload + storage — currently stubbed; blocks every hard-required photo. Highest-priority enabling work.
  • 2 · Category-first conversation step — the one new engine piece; everything else is reuse.
  • 3 · Per-city department map — a small data table; confirm the divergent rows + Peoria water special-case.
  • 4 · Seed N category forms into nf_form_definitions (extend scripts/seed-engine.mjs, today only pothole_report).
  • 5 · Retire /desk/intake — last. It's the only bridge for anonymous voice reports today; don't remove it until the direct-route path lands.
